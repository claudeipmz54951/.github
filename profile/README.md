<p>买之前问什么，这个问题本身有陷阱：很多人以为自己问得挺全，问了价格、问了地区、问了能不能试用，然后签了单，用两周发现限制条款藏在没问的地方。下面把四个最常见的误解摊开讲，每个误解后面接一句真正该问的话。这些问题的共同点是：答案不能是"一般""通常""看情况"，必须落到数字和条款上。</p>

<h2>一、误区一：问了单价就算问清了</h2>
<p>单价是最容易得到、也最没有信息量的一个数字。同样是"每条每月一百二"，含多少流量、超量怎么算、并发几路、能不能换地址，四个变量任何一个不同，实际支出就能差出一倍。</p>
<table>
<thead><tr><th>误区</th><th>被掩盖的问题</th><th>该问的一句话</th></tr></thead>
<tbody>
<tr><td>只比单价</td><td>含流量与并发规格不同</td><td>这个价格含多少 GB、几路并发</td></tr>
<tr><td>只问地区</td><td>城市与 ASN 可能不符</td><td>能不能给 ASN 和 PTR 查询结果</td></tr>
<tr><td>只问能不能试用</td><td>试用可能是另一批资源</td><td>试用地址和正式地址是否同一批</td></tr>
<tr><td>只问能否更换</td><td>更换次数与费用未定</td><td>每月免费换几次，超出怎么收费</td></tr>
</tbody>
</table>
<p>最后一行是重点。有些供应商的"支持更换"指的是到期后换，中途换要额外付费；有些是每月一次免费。这两种承诺听起来一样，用起来差别很大。</p>

<h2>二、误区二：试用能通就算过关</h2>
<p>试用期的地址通常是专门留给测试的，负载低、邻居少，表现自然好。等正式用上，同一批资源被更多用户分担，体验就变了。所以试用要验证的不只是"能不能通"，还有"通得像不像正式环境"。</p>
<h3>用同一套脚本跑对照</h3>
<p>拿到试用地址后，先用固定脚本跑 200 次请求，记录首字节时间的 P95 和失败率；再问供应商要一条正式环境的测试地址（可以只给一小时），用同一脚本跑一遍。两组数字差距超过三成，就要追问资源是否同批。</p>
<h3>别在空闲时段测</h3>
<p>凌晨三点的测试结果参考价值很低。挑你自己的高峰时段测，通常是工作日的上午十点到十二点、下午两点到五点。这个时段的数字才是你日常会遇到的。</p>

<h2>三、误区三：替换政策写在页面上就够</h2>
<p>页面上的"支持免费替换"通常有一串前置条件：需要提供证据、需要在购买后多少天内、每月限几次、替换后的地址不保证同地区。这些条件不写在显眼位置，但会在你真的需要换的时候生效。</p>
<h3>要问的四个细节</h3>
<p>一是判定标准：什么情况算"地址不可用"，由谁判定；二是证据形式：截图、日志还是第三方查询结果；三是处理时长：提交后多久给新地址；四是替换后的地址是否同城市、同 ASN。四个细节里，第三个最影响业务连续性。</p>
<h3>把承诺写进订单备注</h3>
<p>口头或聊天里的承诺，在换对接人之后往往无法追溯。下单时把关键承诺复制进订单备注，或要求对方在订单确认里回写。这一步花两分钟，后面省很多口舌。</p>

<h2>四、误区四：退款只看天数</h2>
<p>退款条款的坑不在天数，在折算方式。常见的三种：按剩余天数比例退、按未使用流量退、以及"首月不退"。同样是七天无理由，落在不同折算方式上，退回的金额可能差一半。</p>
<h3>三个必须确认的口径</h3>
<p>第一，已使用部分按什么单价扣，是折后价还是标价；第二，赠送的流量或试用额度是否计入已用；第三，退款是否收手续费、多久到账。第三条尤其容易忽略，有些渠道退款要扣支付通道费。</p>
<h3>月付比年付更适合试新</h3>
<p>第一次合作建议月付。年付的折扣通常在两成左右，但一旦不合适，退款的复杂度远高于省下的钱。用满三个月确认稳定，再谈年付折扣，顺序别反。</p>

<h2>常见问答</h2>
<h3>对方不愿意给测试地址怎么办？</h3>
<p>答：可以退一步，要求给一小时的单条试用，或者要求提供近期的节点查询截图。两样都不给，说明资源情况可能不方便验证，换一家的成本比继续谈更低。</p>
<h3>报价特别低，是不是一定有问题？</h3>
<p>答：不一定，但要找到低的原因。常见原因是复用人数多、流量包小、或者售后只走工单。把这三项问清，如果都能接受，低价未必不能买；问不清就按高风险处理。</p>
<h3>签合同前要不要先小批量付一个月？</h3>
<p>答：建议这样。首月按最小规格买，跑满一个月再谈量。这一个月的真实数据，比任何承诺都更能说明问题，也能让你在谈价时有依据。</p>
<h3>清单上的问题对方只回一半，还能合作吗？</h3>
<p>答：可以合作，但要按回答的那一半来预期。没答的部分默认没有保障，做好自己兜底的准备，比如备用供应商、可快速切换的配置。别把没答的部分当成"应该没问题"。</p>
